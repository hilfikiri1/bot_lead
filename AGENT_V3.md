# B&BS AI Agent v3

## Цель

Версия 3 превращает Telegram-бота из набора отдельных команд в единый операционный AI-интерфейс Buy & Bring Solutions. Менеджер может писать или отправлять голосовые сообщения обычным языком. Агент хранит рабочий контекст, находит сделки Kommo, формирует приоритеты, готовит тексты и предлагает действия.

## Главный принцип безопасности

Агент разделяет работу на три уровня:

1. **Чтение** — Kommo, диагностика Notion, журнал ошибок. Выполняется сразу.
2. **Подготовка** — КП, follow-up, письмо, запрос фабрике, структура каталога, техническое задание. Агент показывает черновик, но ничего не отправляет.
3. **Внешняя запись** — Kommo, Notion, Gmail и Google Calendar. Выполняется только после отдельной кнопки `Подтвердить`.

Голосовой анализ разговора сохраняется в локальной PostgreSQL-базе. Запись результата в Notion также требует подтверждения.

## Что понимает агент

Примеры запросов:

- `Что мне делать сегодня?`
- `Покажи сделку 135 кормушки` (при нескольких результатах появятся кнопки выбора)
- `Покажи Kommo ID #123456`
- `Сделай КП по этой сделке на польском`
- `Подготовь запрос поставщику по этой сделке`
- `Напиши клиенту follow-up на украинском`
- `Добавь примечание в #123456: клиент ждёт новую цену`
- `Поставь задачу по #123456 завтра в 10:00`
- `Запланируй созвон по этой сделке в пятницу в 15:00`
- `Проверь Notion`
- `Покажи последние ошибки`
- `Синхронизируй открытые сделки с Notion`
- `Сбрось память`

Маленький номер проекта, например `135`, не считается Kommo ID автоматически. Агент ищет его по названию сделки. Явный Kommo ID передаётся как `#123456` или `Kommo ID 123456`.

## Единый агентный контур

```text
Telegram text / voice
        |
        v
Agent planner
        |
        +-- answer/read ----------> ответ менеджеру
        |
        +-- draft ----------------> рабочий черновик
        |
        +-- write ----------------> PendingAgentAction
                                      |
                                      v
                             кнопка подтверждения
                                      |
                                      v
                       Kommo / Notion / Gmail / Calendar
```

Основные модули:

- `app/agent/planner.py` — понимает намерение и выбирает безопасный режим.
- `app/agent/service.py` — единая оркестрация текста и голоса.
- `app/agent/memory.py` — активная сделка, последние сообщения и компактная память.
- `app/agent/digest.py` — приоритеты по открытым сделкам Kommo.
- `app/agent/generation.py` — генерация рабочих черновиков.
- `app/agent/actions.py` — постановка внешних изменений в ожидание подтверждения.
- `app/agent/executor.py` — выполнение только подтверждённых действий.
- `app/agent/notion_gateway.py` — современный Notion Data Sources API.
- `app/agent/audit.py` — журнал интеграций без секретов.

## Память

В PostgreSQL добавлены:

- `agent_sessions` — активная сделка и компактный контекст пользователя;
- `agent_messages` — история диалога с агентом;
- `pending_agent_actions` — ожидающие подтверждения действия;
- `integration_events` — результат и ошибки интеграций.

После каждых нескольких сообщений старая переписка сворачивается в краткую операционную память: решения, обязательства, активные проекты и незакрытые вопросы. Токены, пароли и API-ключи в память не должны попадать.

## Дайджест

`/digest` читает открытые сделки Kommo и ранжирует их по правилам:

- просроченная задача;
- отсутствие следующей задачи;
- длительное отсутствие обновлений;
- недавняя активность.

Дайджест ничего не записывает автоматически. Это список приоритетов для решения менеджера.

## Совместимость

Сохранены существующие функции:

- обработка голосовых и аудиофайлов;
- транскрибация и анализ разговоров;
- существующее создание/обновление лидов Kommo через подтверждение;
- Google Calendar;
- Gmail draft;
- Google Sheets;
- неразобранные сделки Kommo;
- старые Notion-базы для анализа звонков.

Старый `command_router_service.py` оставлен как резервный режим. Основной runtime при `AGENT_ENABLED=true` использует `app/agent/`.

## Реальные ограничения

- Агент не является фоновым автономным сотрудником: он работает по сообщениям и подтверждениям Telegram.
- Качество решений зависит от полноты данных в Kommo и текста разговора.
- Генерация не должна придумывать цену, сертификат, наличие, срок или обещание клиенту.
- Отправка WhatsApp не включена; формируется только текст.
- Перед production-deploy необходимо проверить Railway Variables и выполнить миграцию.
