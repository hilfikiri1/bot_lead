# B&BS Kaizen Journal

Лёгкий личный рабочий дневник владельца компании. Он не является системой контроля сотрудников, трекером настроения или KPI.

## Ежедневный сценарий

Команда:

```text
/evening
```

Также распознаются естественные фразы:

- `Подведём итоги дня`;
- `Хочу рассказать, как прошёл день`;
- `Запиши итоги дня`;
- `Дополни дневник: ...`.

После приглашения можно отправить одно текстовое или одно голосовое сообщение. Не нужно отвечать на пять вопросов отдельно.

Сначала исходный текст или voice transcript сохраняется в PostgreSQL, затем выполняется AI-структурирование. При сбое OpenAI исходная запись остаётся доступной для недельного анализа.

Активное ожидание рефлексии хранится в `AgentSession.context.pending_daily_reflection`, действует не более шести часов и не переходит на следующий локальный день. Slash-команды не становятся дневниковой записью.

## Голос

Используется существующая цепочка:

```text
Telegram audio
→ download
→ transcription
→ agent_service.handle_message
```

При активной вечерней рефлексии агент возвращает `handled=True` до клиентского pipeline. Поэтому дневниковое голосовое:

- не создаёт клиента;
- не создаёт лид;
- не вызывает анализ клиентского звонка;
- не записывается в Kommo.

## Хранение

Таблица `kaizen_journal_entries` содержит ежедневные и недельные записи. Уникальность пользователя, типа и периода защищает от дублей после рестартов и повторных callback.

Обычные ежедневные мысли остаются только в PostgreSQL. Notion получает исключительно подтверждённые карточки улучшений из недельного отчёта.

## Недельный сценарий

Команда:

```text
/week
```

Также распознаются:

- `Подведи итоги недели`;
- `Что ты понял за эту неделю?`;
- `Какие проблемы повторялись на неделе?`.

Анализ использует дневниковые записи с понедельника по воскресенье. Read-only операционная сводка Kommo добавляется best-effort; её сбой не блокирует локальный отчёт.

Повторяющейся считается только проблема с наблюдениями минимум в двух разных днях. При количестве заполненных дней меньше трёх отчёт помечается как недостаточный для системных выводов.

Недельный отчёт предлагает максимум три improvement-кандидата. Карточки Notion не создаются автоматически.

## Notion approval flow

Внешняя запись использует стандартный контур:

```text
proposal
→ validation
→ permission check
→ preview
→ explicit confirmation
→ deterministic executor
→ audit
```

Batch-action: `create_notion_improvements_batch`.

Исполнитель повторно загружает недельную запись, проверяет владельца и период, использует `External ID = kaizen:<weekly_entry_id>:<index>`, сохраняет page IDs после каждого успеха и безопасно продолжает частично выполненный batch.

Используется существующая `NOTION_TASKS_DATA_SOURCE_ID`. Новая база Notion не создаётся.

Минимальные свойства Tasks:

- title: `Задача` или `Name`;
- `Тип` / `Type` со значением `Improvement`;
- `Статус` / `Status` со значением `Todo`;
- `Источник` / `Source` со значением `Kaizen`;
- `Срок` / `Due` — опционально;
- `External ID` — рекомендуется для дополнительной идемпотентности.

Если база или свойства недоступны, локальный недельный отчёт сохраняется, а пользователю предлагается проверить `/notion_test`.

## Доска «Kaizen — улучшения»

Notion view не создаётся автоматически.

1. Открыть базу Tasks.
2. Создать linked view.
3. Выбрать `Board`.
4. Назвать представление `Kaizen — улучшения`.
5. Добавить фильтр `Type = Improvement`.
6. Сгруппировать по `Status`.
7. Использовать существующие колонки `Todo`, `Doing`, `Done` и `Rejected`, если такая опция уже применяется.

Существующие названия статусов код не изменяет.

## Railway variables

```env
AGENT_EVENING_REFLECTION_ENABLED=true
AGENT_EVENING_REFLECTION_HOUR=19
AGENT_EVENING_REFLECTION_REMINDER_HOURS=1

AGENT_WEEKLY_REVIEW_ENABLED=true
AGENT_WEEKLY_REVIEW_WEEKDAY=6
AGENT_WEEKLY_REVIEW_HOUR=19
AGENT_WEEKLY_REVIEW_MIN_DAILY_ENTRIES=2

AGENT_DIGEST_TIMEZONE=Europe/Warsaw
MANAGER_TIMEZONE=Europe/Warsaw
```

`0 = понедельник`, `6 = воскресенье`.

При `AGENT_EVENING_REFLECTION_ENABLED=true` обычный `AGENT_EVENING_DIGEST_ENABLED` не отправляется в тот же вечер. Утренний digest не меняется.

## Production smoke

1. `/evening` → получить одно приглашение.
2. Отправить обычный текст → получить краткое резюме.
3. Повторить `/evening`, затем отправить голосовое → убедиться, что клиент/лид не создан.
4. `Дополни дневник: ...` → проверить обновление той же дневной записи.
5. Нажать `Напомнить через час` → проверить одно напоминание.
6. Нажать `Пропустить сегодня` → повторного scheduled приглашения нет.
7. `/week` → получить локальный отчёт даже при недоступном Notion.
8. Нажать `Создать в Notion` → сначала увидеть PendingAgentAction preview.
9. Отменить → внешних страниц нет.
10. Подтвердить → создано не более трёх карточек без дублей.

## Границы

- дневник не создаёт автоматические задачи из каждой жалобы;
- AI не ставит эмоциональные диагнозы;
- WhatsApp, Gmail и Kommo этим flow не изменяются;
- OpenAI нужен только для структурирования, но не для сохранности raw text;
- scheduler работает внутри текущего web process, поэтому для production должен оставаться один активный scheduler instance либо использоваться PostgreSQL-claim, который уже защищает kaizen delivery от дублей.
