# Phase 1 — надёжность, создание лидов и новый Telegram UX

Дата сборки: 29.06.2026

## Что изменено

### 1. Создание нового лида в Kommo

- Перед записью в Kommo показывается редактируемый предпросмотр.
- Можно изменить номер, название, клиента, товар, бюджет и город.
- Запись выполняется только после нажатия `✅ Создать лид`.
- `pipeline_id` и `status_id` проверяются по данным Kommo.
- Если настроенный этап недействителен, запрос автоматически повторяется без неверной воронки/этапа, и Kommo использует стандартное размещение.
- Добавлена идемпотентность: повторное подтверждение одного и того же разговора не должно создавать второй лид.
- В локальной БД сохраняются `kommo_lead_id`, `kommo_contact_id`, воронка, этап и ссылка на сделку.
- Исправлен сценарий `MissingGreenlet`: после rollback код использует заранее сохранённые scalar ID, а не просроченные ORM-объекты.
- Неудачное действие получает статус `failed`, а не остаётся навсегда `pending`.

### 2. Новый дизайн Telegram-бота

- Единое русскоязычное главное меню.
- Короткие кнопки, карточки, разделители, понятные подтверждения и кнопки возврата.
- Карточка сделки показывает этап, воронку, бюджет, контактные данные, ближайшую задачу, поля и последние примечания.
- Пошаговые мастера для задач и событий вместо строки с символами `|`.
- Профессиональная карточка анализа разговора на русском.
- Сообщение, предназначенное польскому клиенту, остаётся на польском.
- Появился раздел `🧭 Статус аудио` и команда `/jobs`.

### 3. Надёжность аудио

- В PostgreSQL сохраняются состояния: `received`, `downloading`, `transcribing`, `analyzing`, `saving`, `ready`, `failed`.
- Уникальная пара `(telegram_user_id, telegram_message_id)` защищает от повторной обработки одного Telegram-сообщения.
- Redis-lock дополнительно защищает от параллельной обработки.
- Celery worker исправлен и слушает очередь `voice_notes`.
- Добавлены retry и time limit для Celery-задачи.
- Пользователь получает понятные сообщения о прогрессе и ошибке.

### 4. Анализ OpenAI

- Все внутренние поля для менеджера должны формироваться на русском.
- Польскими остаются только клиентские черновики WhatsApp/email для польского лида.
- Схема дополнена подтверждёнными фактами, рисками, задачей менеджеру, сроками, количеством, сертификацией и условиями поставки.
- Неизвестные данные не должны выдумываться.
- Транскрипты и полный ответ AI не выводятся в production-логи.

### 5. Безопасность

- `/admin/*` закрыты заголовком `X-Admin-Key`.
- Если `ADMIN_API_KEY` не настроен, admin API полностью отключён.
- Swagger/OpenAPI отключены в production по умолчанию.
- CORS больше не разрешает все домены.
- Google OAuth routes отключены по умолчанию.
- `DATABASE_URL`, токены и транскрипты не печатаются в логах.
- `.env`, credentials, storage, логи и Python cache исключены из Git.

## Миграция базы данных

Добавлена миграция:

```text
003_phase1_reliability
```

Она:

- добавляет Kommo ID в `clients` и `leads`;
- добавляет статусы обработки в `voice_notes`;
- добавляет уникальность Telegram message ID;
- добавляет `idempotency_key` и `error_message` в `actions`;
- перед созданием уникального ограничения безопасно обезличивает Telegram message ID у старых дубликатов, не удаляя связанные отчёты.

Перед deployment рекомендуется сделать backup PostgreSQL.

## Railway

### Web service `bot_lead`

Pre-deploy command:

```bash
alembic upgrade head
```

Start command:

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8000
```

Обязательные переменные для production:

```env
APP_ENV=production
LOG_LEVEL=INFO
ADMIN_API_KEY=<длинный случайный секрет>
EXPOSE_API_DOCS=false
ENABLE_GOOGLE_OAUTH_ROUTES=false
```

Для direct-режима аудио:

```env
AUDIO_PROCESSING_MODE=direct
```

### Celery worker

Start command:

```bash
celery -A app.celery_app:celery_app worker --loglevel=info -Q voice_notes --concurrency=2
```

Если вы переходите на Celery:

```env
AUDIO_PROCESSING_MODE=celery
```

У worker должны быть те же `DATABASE_URL`, Redis, Telegram и OpenAI variables.

## Проверка после deployment

1. Отправить `/menu`.
2. Открыть `🔌 Проверить Kommo`.
3. Отправить короткое тестовое аудио.
4. Проверить прогресс через `/jobs`.
5. Нажать `📥 Подготовить новый лид`.
6. Изменить название или номер.
7. Подтвердить создание.
8. Повторно нажать старую кнопку и убедиться, что второй лид не создан.
9. Найти созданную сделку и открыть её карточку.
10. Создать тестовое примечание и задачу.

## Что не входит в эту фазу

- Полная двусторонняя синхронизация PostgreSQL ↔ Kommo.
- Голосовые команды с распознаванием намерения.
- Импорт готовых `.txt`/`.docx` транскриптов.
- Полная переработка iCloud CalDAV и `.ics` fallback.

Эти функции остаются для следующих фаз. Пошаговый интерфейс календаря уже улучшен, но backend CalDAV в Phase 1 не переписывался.
